I found five remaining issues:

1. **[P1] Shutdown can still admit new model turns.** `Conversations.close_admission()` sets a flag that `_admit()` never checks. Shutdown then awaits native cancellation before closing the actual TurnRunner gate. A completion notification during that interval can start another turn while shutdown is underway. Close the real admission gate before that first await, including admission already in progress. [Admission](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/conversations.py:374), [shutdown ordering](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/task_runtime.py:277).

2. **[P2] Revoking access does not wake an indefinite peer wait.** Grant changes are persisted, but the notifier sends recipient wakeups only for mailbox events. A waiting peer therefore rechecks authorization only after another event or timeout—which may never happen. R2 explicitly requires revocation wakeups. [Notifier](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/task_history.py:928).

3. **[P2] Visual Questions lost their public contract.** The replacement `ask_user` omits `surface_id` and `answer_action`, although shipped marketplace agents still use them. The interaction projection also omits the surface identifier required by the UI. Additionally, the new answer handler requires a `question_id` correlation that the existing visual Question component does not send. These features need rebuilding through the new Question owner. [Tool schema](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/task_declarations.py:246), [projection](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/routes/interactions.py:315), [UI](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/external/gact-tui/web/src/components/clio/question-surface.tsx:37).

Cancellation can succeed and subsequently fail while constructing its response for the same reason. Normalize once and use the authorized canonical handle throughout. [Answer path](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/question_surface.py:73), [cancel response](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/routes/tasks.py:313).

[Consumption projection](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/a2ui_actions/delivery.py:125).
