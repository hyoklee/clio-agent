## Architecture

The committed design matches `docs/design/task-replacement-plan.md` sections 3 and 4. `TaskHistory` (`src/clio_agent/gact/task_history.py:60`) is the only Core writer; its dictionaries are rebuilt from Core on `restore` (`task_history_projection.py:293`) and a failed write flips `requires_recovery`, which blocks new durable admission until `CoreRecovery` reconciles (`core_recovery.py:63`). Execution owners only publish snapshots: `NativeTools` (`native_tools.py`), `ExternalTasks` (`external_tasks.py`), `Conversations` (`conversations.py`) and `QuestionCommands` (`questions.py`). `TaskSnapshot.validate_custody` (`arc/task_types.py:203`) stops backend rebinding and terminal reopening at the writer, so no cross-owner transition table exists.

- **Stable sessions, finite assignments.** `_admit` mints a successor only when eligible mail arrives after a terminal assignment (`conversations.py:308-324`); `_finish_segment` yields by default while work, dependencies, gates or eligible mail remain (`conversation_assignments.py:251-269`); `require_admission` walks parent handles and honors predecessor lineage (`conversations.py:517`). Restart cancels, waits through the shared wait, refuses on uncertain settlement, and links the successor (`conversation_controls.py:350-467`). Inference permits are taken only around the model call (`conversations.py:551`, used at `agents/clio_react.py:683`). One session thread per segment with retirement joined before release (`turn_runner.py:172-230`).
- **Messaging.** `SessionMail.peer` authorizes by `TaskAccess` and rejects successor addressing by stale exact grants (`session_mail.py:396-473`); delivery is rechecked at staging and again at commit (`session_mail.py:82-90, 239-263`). Grants are human-only REST with bearer auth (`routes/tasks.py:402-474`); delegation grants a child only a reply channel (`conversation_assignments.py:508-524`). Workflows use ordinary spawns, shared waits and checkpoints through the same writer (`workflows.py:492-791`).
- **Observation and waits.** Waits are listener-driven, unbounded by default, return `task_state_uncertain` members as pending with no acknowledgement, and recheck revocation after off-lock reads (`task_operations.py:274-379`). Output pages are task-local Core chunks with offsets and pattern spans (`task_output_pages.py:31`). Query seeks immutable per-scope orderings and bounds candidates (`task_operations.py:121-193`).
- **Questions.** `ask_user` posts under the parent assignment and returns at once through the short FastMCP boundary (`task_declarations.py:276-415`, `builtin_boundary.py:125-221`); answers, cancels and expiry arbitrate under the writer lock (`questions.py:296-412`); collection is explicit through `wait_tasks`/`get_task_result` and acknowledged only by the recipient-input record (`task_declarations.py:53-76`, `session_mail.py:283-361`). Human and MCP-elicitation answers share this record; MCP input keys bind to the full request id without splitting (`external_task_inputs.py:121-157`).

Removal is intact: the guard (`scripts/check_task_replacement_removal.py`) denies module paths, names, state, config and aliased imports, with a single string-literal exemption for historical decoding. I found no production import of a retired owner.

## Source findings

1. **Medium. Revocation racing a collection fails the whole assignment.** `StepRecorder.step_done` commits collections without catching `TaskAccessDenied` (`agents/clio_react_record.py:620-626`), while `commit_input` deliberately catches it (`clio_react_record.py:420-430`). The exception is a `ValueError`, not `ClioError`, so `ClioReAct.forward` does not record it (`agents/clio_react.py:399`); it propagates to the turn, becomes `outcome.error`, and `_finish_segment` marks the assignment terminal `failed` (`conversation_assignments.py:290-299`). A human revoking a peer grant between a `wait_tasks` RPC and its recording therefore ends the recipient's assignment. The R33 case asserts the raise but not this downstream outcome (`tests/test_arc/test_task_read_recovery_r33.py:253`). Catch it in `step_done` and leave the observation behind the existing placeholder.
2. **Medium. Wait collection drops observe-only metadata.** `_collected` records only `read_handles` (`task_declarations.py:53-76`); observe-only and uncertain pending rows from `_outcomes` (`task_operations.py:343-358`) are not carried as `observe_handles`, so `SessionMail.commit` never rechecks observe rights for them (`session_mail.py:217-225`). This is the gap the R33 "trusted query/observe metadata" correction closed for query and observe but not for wait.
3. **Medium (F03). Shipped projections still scan.** `/async-processes`, `/agent-tasks` and `/sessions/{sid}/questions` call `query(limit=10000)` (`routes/tasks.py:245, 256, 327`), which examines up to 40000 candidates per request, and `/v1/questions` uses the recursive `tree_handles` walk (`routes/tasks.py:350`). GACT refetches `sessionAgentTasks` on every live child change (`web/src/hooks/use-session-agent-tasks.ts:25-33`).
4. **Low. Transient model errors terminate assignments.** Any `outcome.error` becomes `status=failed, settlement=confirmed` (`conversation_assignments.py:290-299`). A provider outage on a child ends the child and notifies the parent as failed; on a root it mints a successor on the next message. The plan lists yield, steering, wakes, recovery and pause as assignment-preserving but is silent on segment errors. This needs an explicit decision, not necessarily a change.
5. **Low. `observe_tasks` accepts `timeout_s` and ignores it without a pattern** (`task_operations.py:442-456`); the schema and alias advertise it (`task_declarations.py:216-224, 484-497`). Either reject the combination or document the no-op in the tool description.
6. **Low. Orphan child session on a Core write failure.** `spawn` creates the session store row before the assignment snapshot (`conversation_assignments.py:459-463`); a retry under the same invocation resolves `existing` from history only and creates another session.
7. **Low (maintainability).** Policy evaluation and permission snapshots run under the global writer lock during native admission (`native_work.py:176-223` calling `task_runtime.py:54-111`); `_confirm` calls `self.work["shell"]._check_admission` for every root (`native_tools.py:430`); `_arrivals` renders a full staging batch each iteration just to test emptiness (`agents/clio_react.py:412-419`) and `_admit` stages twice (`conversations.py:270-288`).
8. **Low (prompts).** Marketplace guidance still says a child's `ask_user` keeps the child "running" and that a declined question fails the child's task (`external/clio-agent-marketplace/factorio-flat/skills/coordinate-scientific-work/references/task-lifecycle.md:19-26`). Under the replacement the child yields and a cancelled Question does not fail the assignment. The marketplace contract test checks only legacy names (`tests/test_native_orchestration_prompt_contract.py`). Task tools do auto-attach to agents that declare only `ask_user` (`gact/agents/auto_tools.py:118-119, 201`), so D01 guidance reaches them.

GACT is consistent with the server: Runs pages by cursor and shows null totals honestly (`web/src/routes/runs-page.tsx:322-344, 723-727`), cancel confirmations name descendant work, restart is confirmed separately (`web/src/components/clio/async-task-list.tsx`), and grants keep read/observe/message/control separate (`web/src/components/clio/session-access.tsx`). `controlSubagent` posts an unused `{fresh:false}` body (`packages/core/src/v3/task-repository.ts:173`), harmless.

## Qualification

- The fresh suites are good quality: real Core via the `arc` fixture, real FastMCP/Docket roots (`tests/test_arc/test_native_owner_contracts.py`), writer fault injection, Stop/retry/cancel races (`test_task_retirement_contracts.py`), concurrent revocation during slow reads (`test_task_read_concurrency_r33.py`), and migration run twice. The ledger's "constructed, unexecuted" status is accurate for R33 rows.
- **Blocking.** 40 test modules still import retired modules (for example `tests/test_gact/test_turn_runner_s1.py`, `test_question_expiry_publication.py`, `test_plan_exit.py`); exact-head CI cannot pass. `test_turn_runner_s1.py:216-237` asserts a grace-window hard cancel against a constructor and `drain(grace=...)` that no longer exist, encoding the cutoff the plan removes.
- The receipts the ledger cites (`task-replacement-*-checks.json`) are not in the snapshot, so the "passed" component claims are unverifiable here. `Z01` is the only row marked pass; everything from F01 through R6 remains blocked, which matches what the source can support.
- Ledger hygiene: the compatibility table reuses IDs C01 through C03 that already name the authorization rows (`docs/qualification/task-replacement-acceptance.md:41-43` versus `150-152`).
- Missing regressions for findings 1, 2, 3 and 5 above.

Recap: the ownership and removal design is sound and faithfully implemented, with no retired authority restored. Source is not ready because a grant revocation can fail an unrelated assignment, wait collections skip observe rechecks, and shipped routes still scan. Qualification is not ready because the legacy test inventory is unmigrated, one legacy test asserts a removed contract, cited receipts are absent, and no live gate has run.
