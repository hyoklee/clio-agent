## Findings

**1. Medium, source: Stop or pause during a child's SessionStart hook bricks the child permanently.** State moves to `started` before the hook runs and only `completed` clears it (`sessions.py:515-545`). The dispatcher raises `HookCancelled` when the stop token is set, including before any adapter has run (`src/clio_agent/gact/hooks/dispatcher.py:140-141`), so a plain human Stop leaves the row at `started`. Every later segment then fails at `turn_forward.py:94` and becomes a failed assignment (`src/clio_agent/gact/conversations.py:700-707`). Resume and restart create successors on the same session that fail the same way. No control anywhere mutates that state (grep: only `sessions.py`). The map promised "explicit recovery choices"; the prompt pack only says to inspect the stored error (`src/clio_agent/prompt_packs/builtin/runtime/clio.runtime.tasks.md:88-91`). Fix within existing owners: let the dispatcher report cancellation before any invocation as no-effects, and add an authenticated human acknowledgement for inspected hook effects, or state in the ledger that abandonment plus respawn is the only recovery.

**2. Medium, lock scope: child metadata preparation still runs under the global task writer.** `spawn.create` holds `serialized(writing=True)` around `create_child` (`conversation_assignments.py:425, 483-495`), which performs blueprint discovery and MCP descriptor validation (`task_runtime.py:143-167`, `src/clio_agent/gact/spawn_context.py:36-52`) and a full rewrite of the sessions file (`sessions.py:347-358, 451-452`). All task reads share that RLock (`src/clio_agent/gact/task_history.py:69, 481, 626-633`), so slow blueprint resolution stalls queries, Question posts and admission for every session. The R36 "slow startup" test stalls only the hook, so this scope is uncovered. Resolve the agent target before taking the writer; it is pure input.

**3. Low, F03 inputs to measure.** Every spawn calls the startup-only full input scan (`conversation_assignments.py:117` into `task_history.py:345-361`, whose docstring says "never during hot reads"), and each child initialization flushes the whole sessions file three times (`sessions.py:501, 525, 544`). R36 defers this to F03; these are the concrete items F03 must measure.

**4. Low, documentation drift the AST guard cannot see.** Docstrings still describe removed owners: the agent-task registry (`src/clio_agent/gact/session_descendants.py:3-13, 43-48`), `turn_spawn._child_workflow_state` (`src/clio_agent/gact/delegation.py:316-317`), legacy spawn/wait names (`turn_forward.py:15-18`), and the SEP-2663 store comment (`sessions.py:296-305`).

**5. Maintainability note.** `Conversations` is one owner spread over four modules as free functions bound to the class (`conversations.py:150-154, 732-744`), with `conversation_controls.py` and `workflows.py` sitting at 795 and 798 lines against the 800 cap. The size guard passes by partition, not cohesion.
