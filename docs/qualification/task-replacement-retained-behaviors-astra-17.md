Native execution, one conversation owner, one Core mailbox and one admission path are sensible boundaries. **I would keep that direction and stop adding architectural layers.**

Five issues remain in the current source:

1. **Missing conversation context is no longer reconstructed.** The loop discards supplied history, reads the Core context lane, and has no production caller of the retained empty-context restoration function. A conversation with preserved transcript evidence but a missing context lane can continue without its earlier inputs and tool results. The plan’s F06 requirement already covers this; it needs implementation and retained regression coverage. [Loop initialization](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/agents/clio_react.py:333)

2. **Cancelling plan approval can leave the conversation blocked.** Creating the approval installs an `execution_gate`. Answering clears it, but cancelling the Question only closes its task record. The conversation then rejects subsequent input because the gate remains. Cancellation needs to finish the existing plan-resolution behavior. [Question cancellation](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/task_runtime.py:112), [admission gate](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/conversations.py:173)

3. **Workflow continuation can stall on an already completed step.** Recovery reloads accumulated state, then evaluates each step’s gate before checking its saved execution. For example, step A requires an absent value and creates it; resuming while B is running evaluates A again and fails. Completed steps must resume from recorded progress. [Workflow continuation](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/workflows.py:540)

4. **An explicit workflow execution deadline has become only a waiting deadline.** `WorkflowStep.timeout_s` still promises an absolute execution budget, but the implementation passes it to `wait` and returns on timeout without cancelling the child. Removing old polling machinery should preserve that declared limit. [Declared contract](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/workflows.py:74), [current handling](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/workflows.py:566)

5. **A second submission on a closed Question surface can become ordinary feedback.** Automatic surface lookup excludes terminal Questions. A fresh click without an explicit Question ID therefore loses its answer routing and can enqueue a new agent turn. Preserve the surface’s answer identity so stale answers are rejected. [Surface lookup](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/questions.py:125), [feedback fallback](C:/Users/jaime/.codex/worktrees/agent-facing-async-tasks/clio-agent/src/clio_agent/gact/a2ui_actions/delivery.py:108)
